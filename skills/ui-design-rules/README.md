# ui-design-rules: what I think it is

A cheat sheet of front-end design habits that make an interface feel "designed" instead of AI-default. Claude reads `SKILL.md` automatically when you ask it to build, restyle or review UI.

What's inside, in plain words:
- **CSS craft (section 1):** small tricks with a big visual payoff, like inner corner radius = outer radius minus padding, see-through borders, OKLCH colours so shades look even, and `100dvh` so mobile full-screen sections fit.
- **Colour (2):** two calm base colours plus ONE small pop of the opposite colour to show the eye where to look.
- **"Unslop" checklist (3):** how to turn a generic AI screen into a clean one, using an OTP code screen as the example.
- **Motion (4, 6, 8.3):** Disney's animation principles applied to buttons and menus, plus timings. Most UI motion stays under 300 ms; only one-off page reveals run longer.
- **UX laws (5):** Fitts, Hick, Jakob, Doherty and others, each turned into a concrete rule.
- **Hierarchy (7):** one big thing, a few medium, the rest quiet.
- **Page patterns (8):** a header that hides when you scroll down, and a bold one-accent landing page.
- **Polish details (9):** skeleton screens, undo instead of "Are you sure?", tabular numbers, idempotency keys and more.

My take: this is the most useful of the three day to day. Treat the case-study numbers (e.g. the Joseph Joseph header test) as one company's result, not a law. They're labelled that way in the file.
